# BRIX — бета-тест (чистые HTML + CSS + JS)

Та же самая игра, что и раньше, но теперь **без Next.js и сборки** —
только HTML, CSS и JavaScript. Каждый файл отвечает за свою часть,
всё разложено по папкам, в коде русские комментарии.
Стиль, функции и сохранения перенесены один-в-один из старой версии.

## Как запустить

### Способ 1 — Windows (проще всего)
Двойной клик по файлу **START-GAME.bat** — игра откроется на http://localhost:8080

### Способ 2 — любая система (через терминал)
В папке игры выполнить:
```
python -m http.server 8080
```
и открыть в браузере: http://localhost:8080

### Способ 3 — совсем просто
Двойной клик по **index.html** — тоже работает: модель топора и звуки рубки
встроены прямо в код (js/game/embeddata.js), так что ничего не потеряется.
Но лучше способ 1 или 2.

## Управление в игре

- **WASD** — движение
- **мышь** — камера (клик по экрану захватывает курсор)
- **SHIFT** — бег
- **ПРОБЕЛ** — прыжок
- **ESC** — пауза (продолжить / отключиться)
- **1–7 / колесо мыши** — слоты хотбара (7 — ПЛАН СТРОИТЕЛЯ)
- **E** — открыть/закрыть инвентарь (перетаскивай предметы мышью)
- **Z (только с планом в руках)** — меню строительства: фундамент /
  стена / потолок; **ЛКМ** ставит выбранную деталь с магнитом к сетке
- **ЛКМ с ТОПОРОМ** (слот 1 — каменный, слот 6 — железный) — рубка деревьев → древесина.
  Дерево рубится ТОЛЬКО по стволу: удары по листве ничего не дают
- **Стволы деревьев и камни с рудой — сплошные**: сквозь них не пройти
- **ЛКМ с КАМЕННОЙ КИРКОЙ** (слот 4) и **С ЖЕЛЕЗНОЙ КИРКОЙ** (слот 5) — добыча руд: железо (silver ore), сера (gold ore), камень → предметы в инвентарь. Камень добывается ТОЛЬКО киркой
- **Железная кирка** (слот 5) с v0.2.10 держится ОДНОЙ правой рукой ТОЧНО КАК ТОПОР (тот же хват и размер, левая рука спрятана), удар — один, вперёд; голова кирки повёрнута лезвием ВПЕРЁД
- **Железный топор** (слот 6, модель и иконка пользователя) держится ОДНОЙ правой рукой, левая рука спрятана, удар — один, вперёд (atk1); лезвие повёрнуто ВПЕРЁД

## Что нового в v0.4.6 — СТРОИТЕЛЬСТВО: план строителя, фундамент, стена, потолок

1. **ПЛАН СТРОИТЕЛЯ** — новый предмет в **7-м слоте** хотбара (иконка —
   синий ватман `assets/icons/building_plan.png`). В руках — синий
   ватман-свиток с чертежом домика (как в Rust). Возьми план в руки
   (клавиша **7**) и жми **Z** — откроется меню строительства.
   **Если плана в руках нет — Z НЕ работает** (как просил игрок).
2. **МЕНЮ КАК В РЕФЕРЕНСЕ** — радиальное колесо: 3 детали по кругу
   (ФУНДАМЕНТ справа, СТЕНА слева-снизу, ПОТОЛОК слева-сверху),
   в центре — иконка, название и описание выбранной детали. Выбор —
   НАПРАВЛЕНИЕМ МЫШИ от центра экрана (работает под pointer lock),
   ЛКМ — выбрать и закрыть, Z/Esc — закрыть.
3. **3 ДЕТАЛИ** (пока три, как просил игрок):
   - **ФУНДАМЕНТ** — палуба 3×3 м на **4 ТОЛСТЫХ НОГАХ** (ноги разной
     длины: палуба СЛЕДУЕТ РЕЛЬЕФУ, верх — по самой высокой точке
     клетки). Если рядом есть фундамент — **МАГНИТИТСЯ К НЕМУ ПО
     ВЫСОТЕ**. По палубе можно ХОДИТЬ, сквозь неё сбоку не пройти.
   - **СТЕНА** — ставится ТОЛЬКО на один из **4 КРАЁВ фундамента**
     (магнит к краю, высота — от фундамента). Сквозь стену не пройти
     (полноценная коллизия).
   - **ПОТОЛОК** — ставится ТОЛЬКО над клеткой, **У КОТОРОЙ ЕСТЬ
     СТЕНА** (стена без фундамента и потолок без стены — красный
     призрак, сервер откажет). По потолку тоже можно ходить.
4. **ПРИЗРАК** — полупрозрачная деталь (зелёная — можно ставить,
   красная — нельзя) показывает будущую постройку с магнитом к сетке
   3×3 м. ЛКМ — поставить. Звук — один из 3 сэмплов строительства
   пользователя (`Construction_Wooden_Build_03/04`,
   `Construction_Wooden_PickUp_04`) — играют РАНДОМНО при каждой
   установке (и у чужих построек — с затуханием по дистанции).
5. **ТЕКСТУРА ДЕРЕВА МНОГОСЛОЙНАЯ** (canvas, 8 слоёв): базовый
   градиент → планки с разной яркостью → волокна → тёмные стыки со
   светлой кромкой → сучки → гвозди с бликом → грязь/потёртости →
   попиксельный шум. Свои варианты: палуба (горизонтальные планки),
   стена (вертикальные), потолок (светлее), ноги (тёмный брус).
6. **СИНХРОНИЗАЦИЯ — ПОСТРОЙКИ ЖИВУТ НА СЕРВЕРЕ**: клиент шлёт заявку
   `bplace`, сервер проверяет правила (фундамент под стеной, стена
   под потолком, клетка/край свободны), берёт ВЫСОТУ ИЗ СВОЕГО
   ФУНДАМЕНТА и рассылает `bnew` ВСЕМ. Снапшот построек едет в
   welcome (`objs.bd`) — **новые игроки сразу видят дом**. Постройки
   хранятся в `world-objs.json` (v4) — **переживают перезапуск
   сервера**. Без сервера (вкладки) — BroadcastChannel + localStorage.
7. **СТРАХОВКА**: если работает СТАРЫЙ server.js (не знает `bplace`),
   постройка применяется локально, и игра ЯВНО говорит об этом:
   «Старый server.js не знает строительства: дом виден только вам».
8. Протокол: `welcome.ver` 44 → **45**. Хотбар расширен до 7 слотов
   (клавиши 1–7, колесо мыши, E — как раньше).

## Что нового в v0.4.2 — лут без «фокусов», 20 ячеек, падающие дропы, прицел-точка

1. **ЛУТ ПОЯВЛЯЕТСЯ В ИНВЕНТАРЕ МГНОВЕННО** — исправлены
   «исчезновения с фокусами» (взял трубу — исчезла; взял пружины —
   вернулись трубы). Причина: фоновая вкладка браузера «просыпается»
   раз в ~2 с, и ответ сервера (cbloot) доезжал с задержкой — предмет
   добавлялся «задним числом». Теперь взятие ОПТИМИСТИЧНОЕ: клик —
   предмет сразу в инвентаре, сервер только подтверждает (tid) или
   откатывает (cbdeny — «Инвентарь полон» / «подойди ближе»).
2. **В ЛУТ-МЕНЮ ВСЕ 20 ЯЧЕЕК РЮКЗАКА** (5×4, как в обычном
   инвентаре) + хотбар 6. Раньше выводилось только 14: инвентарь в
   игре — 26 слотов (6 хотбар + 20 рюкзак), а лут-меню резало список.
3. **ДРОПЫ С БОЧЕК ВИДНЫ И ПАДАЮТ**: причина невидимости — tick
   каждый кадр опускал дроп на высоту РЕЛЬЕФА (внутрь насыпи чекблока),
   отменяя высоту площадки. Теперь единая высота (насыпь/рельеф),
   дроп ПАДАЕТ с бочки с гравитацией, 2 отскока и ложится на ровную
   вершину. Модели крупнее (скрап 0.32 м ржавая груда, пружина
   0.11 м) и всегда собраны кодом.
4. **ЯЩИК И ДРОПЫ РЕАГИРУЮТ ТОЛЬКО ПОД ПРИЦЕЛОМ** (конус ~10°),
   прицел теперь — маленькая точка вместо креста.

## Если ничего не появилось (проверка за 30 секунд)

1. **Хотбар появляется только В ИГРЕ, а не в меню.**
   Путь: меню → **ИГРАТЬ** → дождись конца загрузки мира (полоса до 100%).
   После спавна внизу по центру будет хотбар (6 слотов), рука с топором — справа.
   **E** — инвентарь, **ЛКМ** по дереву вплотную — рубка.

2. **Как понять, что браузер взял НОВЫЕ файлы (главная проверка).**
   Внизу слева в меню должна быть строка: `v0.3.0 · мультиплеер: игроки и запасы синхронно · сборка 14.11.2026 · ✓ сборка v0.3.0 — все файлы на месте`, а рядом — ссылка **«обновить кэш»**.
   - Строка есть и зелёная — всё хорошо, заходи в ИГРАТЬ.
   - Строки нет, версия старая, или «✗ нет новых скриптов» — браузер показывает старые файлы из кэша (это обычное дело: простые серверы кэш не отключают). Нажми ссылку **«обновить кэш»** прямо в меню (или **Ctrl+Shift+R** на Windows / **Cmd+Shift+R** на Mac) — страница перезагрузится уже с новыми файлами.
   - Нажал «обновить кэш», а версия всё равно старая — значит сервер отдаёт другую папку (см. пункт 5).

3. **Ошибки 404 на `.woff2` (шрифты Oswald / Roboto Condensed).**
   Значит, в папке, которую раздаёт сервер, **нет папки `assets/fonts/`**.
   Ты заменил только часть файлов. Замени папку игры **целиком** папкой `brix/`
   из архива — там уже лежат все шрифты, иконки, модель топора и звуки.

4. **Ошибка `[BRIX] Не хватает новых файлов игры!`**
   Сервер отдаёт старый `index.html` или в нём нет новых скриптов
   (`js/game/glb.js`, `sfx.js`, `firstperson.js`, `inventory.js`).
   Возьми `index.html` и папку `js/` из архива целиком.

5. **Заменил файлы, но версия в меню всё равно старая — сервер отдаёт ДРУГУЮ папку.**
   Так бывает, если игра установлена как npm-пакет или запускается скриптом из проекта:
   сервер может раздавать копию игры из `node_modules/...` или из другой папки,
   а ты меняешь файлы в другом месте. Проверь:
   - открой `http://localhost:8080/assets/models/stone_axe.glb` — 404? Значит сервер раздаёт не ту папку;
   - поищи в проекте (поиском по имени папки) ВСЕ папки с файлом `index.html` игры и замени файлы в той, которую реально запускает сервер (если игра стоит из npm — это папка внутри `node_modules`);
   - после замены файлов перезапусти сервер.

6. **Сообщение `Scripts "build/three.js" and "build/three.min.js" are deprecated…`**
   Это **не ошибка**, а предупреждение Three.js — на игру не влияет, игнорируй.

Быстрая проверка, что сервер отдаёт нужные файлы — открой в браузере:
- `http://localhost:8080/assets/fonts/Oswald-400-cyrillic.woff2` — должен скачатьcя файл
- `http://localhost:8080/assets/models/stone_axe.glb` — тоже

Если оба дают 404 — сервер запущен **не из той папки** (запускай `python -m http.server 8080`
именно внутри папки `brix/`, где лежит `index.html`).
